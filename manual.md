# HotelHub — инструкция по локальному запуску и тестированию

Этот документ — пошаговая инструкция: как поднять проект с нуля, в каком
порядке наполнить его демо-данными, как прогнать автотесты и что именно
проверять руками в браузере по каждому модулю. Все команды даны как есть,
скопируйте и выполняйте по порядку.

---

## 1. Локальный запуск с нуля

### 1.1. Требования

- Python **3.12+** (проект использует Django 6.0.5, который требует 3.12+)
- pip

### 1.2. Виртуальное окружение и зависимости

```bash
cd HotelHub
python -m venv venv

# Активация окружения:
source venv/bin/activate        # Linux / macOS
venv\Scripts\activate           # Windows (cmd/PowerShell)

pip install -r requirements.txt
```

Ожидаемый вывод в конце — что-то вроде:
```
Successfully installed Django-6.0.5 Pillow-11.0.0 asgiref-3.11.1 ... openpyxl-3.1.5 reportlab-4.4.10 python-docx-1.2.0 ...
```

### 1.3. Миграции

```bash
python manage.py migrate
```

**Успех выглядит так** (в конце списка операций):
```
Running migrations:
  Applying users.0001_initial... OK
  ...
  Applying rooms.0003_room_image... OK
```
Если вы видите `No migrations to apply.` — значит база уже актуальна, это тоже нормально.

**Если увидите ошибку** вида `django.db.utils.OperationalError` — скорее всего,
в проекте лежит старый `db.sqlite3` от другой версии моделей. Удалите его и
повторите миграцию:
```bash
rm db.sqlite3          # Linux/macOS
del db.sqlite3         # Windows
python manage.py migrate
```

### 1.4. Наполнение демо-данными (сиды) — СТРОГО В ЭТОМ ПОРЯДКЕ

Проще всего — одной командой, которая сама вызывает всё по порядку:

```bash
python manage.py seed
```

**Успешный вывод:**
```
Запуск сидеров по приложениям:
Создаю пользователей...
  + guest / guestpass123
  + aizhan / aizhan2026
  ...
  + admin / admin12345 (суперпользователь)
Готово. Пользователей в базе: 5
Создаю отели...
  + Grand Astana (Астана)
  ...
Готово. Создано новых: 6. Всего отелей: 6
Создаю номера...
Готово. Создано новых: 24. Всего номеров: 24
Создаю бронирования...
  + Бронь №1: Grand Astana — номер 406 (...)
  + Бронь №2: Grand Astana — номер 306 (...)
Готово. Всего бронирований: 2

Готово! База наполнена демо-данными.
Демо-доступы:  guest / guestpass123   ·   admin / admin12345
```

Команду можно запускать сколько угодно раз — она **идемпотентна**, повторный
запуск не создаст дублей (это отдельно проверяется тестами, см. раздел 2).

Если нужно **пересоздать всё с нуля**, удалив старые демо-данные:
```bash
python manage.py seed --flush
```
(суперпользователей флаг не трогает).

**Если хотите вызвать сидеры по одному** — важен именно этот порядок
(каждый следующий зависит от предыдущего):
```bash
python manage.py seed_users      # 1. пользователи (guest, admin и др.)
python manage.py seed_hotels     # 2. отели (независимы, но нужны для номеров)
python manage.py seed_rooms      # 3. номера (нужен hotels)
python manage.py seed_bookings   # 4. брони (нужны users + rooms)
```
Если вызвать `seed_bookings` раньше `seed_users`/`seed_rooms` — команда не
упадёт, а вежливо напишет:
```
Нужны пользователь guest и хотя бы 2 номера. Сначала выполните seed_users и seed_rooms.
```

### 1.5. Папки для картинок (создать один раз)

Демо-путь к обложкам/фото уже прописан в базе сидерами, но сами файлы вы
добавляете самостоятельно — см. раздел 5 этого документа. Папки уже лежат
в архиве:
```
media/hotels/covers/demo/
media/rooms/images/demo/
```
Если их нет — создайте:
```bash
mkdir -p media/hotels/covers/demo media/rooms/images/demo
```

### 1.6. Запуск сервера

```bash
python manage.py runserver
```
Откройте в браузере: **http://127.0.0.1:8000/**

Демо-доступы:
| Роль | Логин | Пароль |
|---|---|---|
| Обычный пользователь | `guest` | `guestpass123` |
| Администратор (доступ в `/admin/` и импорт отелей) | `admin` | `admin12345` |

## 2. Автотесты

### 2.1. Полный прогон

```bash
python manage.py test
```

**Успех выглядит так:**
```
Found 102 test(s).
Creating test database for alias 'default'...
System check identified no issues (0 silenced).
......................................................................................................
----------------------------------------------------------------------
Ran 102 tests in ~100s

OK
Destroying test database for alias 'default'...
```
Каждая точка `.` — один прошедший тест. Строка `OK` в конце — все 102 теста
зелёные.

**Как выглядит провал теста** (для примера, если что-то сломается):
```
FAIL: test_create_booking_rejects_double_booking (bookings.tests.BookingServiceTests)
Нельзя забронировать уже занятый на эти даты номер.
----------------------------------------------------------------------
Traceback (most recent call last):
  File ".../bookings/tests.py", line 178, in test_create_booking_rejects_double_booking
    ...
AssertionError: ValidationError not raised
----------------------------------------------------------------------
Ran 102 tests in 101.4s

FAILED (failures=1)
```
Вместо точки на месте упавшего теста будет `F` (провал) или `E` (ошибка
выполнения), а в конце — `FAILED (failures=N)` вместо `OK`.

### 2.2. Тесты одного приложения

```bash
python manage.py test hotels     # 29 тестов: модель, список+пагинация+сортировка+min_price, детали, рейтинг, картинки, импорт/экспорт, сидер
python manage.py test rooms      # 30 тестов: модель, список, поиск по датам, сортировка, пагинация, occupied_today (дефект №4), форма, сидер
python manage.py test bookings   # 24 теста: сервисный слой, отмена брони, GET-защита, сидер
python manage.py test users      # 13 тестов: регистрация, вход/выход, open redirect, аватар, сидер
python manage.py test core       # 6 тестов: главная страница, оркестратор seed
```

### 2.3. Дополнительные проверки (рекомендуется перед сдачей/защитой)

```bash
python manage.py check                          # статические ошибки конфигурации — должно быть "System check identified no issues"
python manage.py makemigrations --check --dry-run  # база синхронна с моделями — должно быть "No changes detected"
python manage.py check --deploy                 # предупреждения безопасности для продакшена (в DEBUG-режиме несколько предупреждений — это ожидаемо)
```

## 3. Что проверять руками в браузере — по модулям

### 3.1. `core` — главная страница
- Открыть `/` — виден блок статистики (число отелей / свободных номеров / городов), топ-3 отеля, топ-3 свободных номера.
- Все ссылки навигации (`Отели`, `Номера`, `Войти`/`Мои брони`) ведут на правильные страницы.

### 3.2. `hotels` — каталог отелей
- `/hotels/` — список отелей карточками по 6 на страницу, внизу пагинация; поиск по городу (`?city=Астана`); сортировка «По рейтингу / Сначала дешевле / Сначала дороже».
- Цена на карточке и на странице отеля — «от N ₸», посчитанная по реальным номерам отеля (`min_price`), а не отдельное поле `Hotel.price`.
- Кнопки экспорта **CSV / Excel / PDF / Word** — каждая скачивает файл нужного формата (проверьте, что файл открывается).
- Кнопка **«Импорт CSV/Excel»** видна только под `admin` (под `guest` её нет).
- `/hotels/import/` под `guest` — должна вернуть **403 Forbidden**.
- `/hotels/import/` под `admin` — форма загрузки, поддерживает `.csv` и `.xlsx`.
- Страница одного отеля `/hotels/<id>/` — обложка (или плейсхолдер), список номеров этого отеля с актуальным бейджем занятости (см. 3.3).

### 3.3. `rooms` — каталог номеров
- `/rooms/` — список номеров по 6 на страницу, внизу пагинация.
- Поля **«Заезд» / «Выезд»** — выберите даты, номера, забронированные на эти даты, должны пропасть из списка.
- **Сортировка** «Сначала дешевле/дороже» — меняет порядок карточек.
- Попробуйте выезд раньше заезда — должна появиться ошибка «Дата выезда должна быть позже даты заезда», список при этом не должен падать 500-й ошибкой.
- Переход на страницу 2 (`?page=2`) с одновременно выбранными датами/сортировкой — параметры поиска должны сохраниться в ссылке.
- **Бейдж «Свободен» / «Занят сегодня»** (дефект №4, исправлен в этом аудите): создайте в админке бронь на СЕГОДНЯ для какого-нибудь номера — на карточке и на странице этого номера должно появиться «Занят сегодня»; у номера с бронью только на будущие даты бейдж сегодня должен оставаться «Свободен». Кнопка «Забронировать» при этом остаётся видимой — занятость сегодня не мешает забронировать номер на другие даты.

### 3.4. `users` — аккаунт
- `/users/register/` — регистрация нового пользователя, автоматический вход после регистрации.
- `/users/login/` — вход; при переходе на страницу входа с закрытой страницы (`?next=...`) после входа должно вернуть обратно.
- `/users/profile/` — email, телефон, дата регистрации, список своих броней, кнопка «Выйти» (это POST-форма, не ссылка).
- `/users/profile/edit/` — загрузка аватара, смена email/телефона.

### 3.5. `bookings` — бронирования
- Со страницы номера — кнопка «Забронировать» (видна только вошедшим; гостю показывается «Войдите, чтобы забронировать»).
- Создать бронь с корректными датами — появляется в `/bookings/` со статусом «Ожидает подтверждения».
- Кнопка «Отменить» — статус меняется на «Отменена», номер снова появляется свободным в поиске по тем же датам.
- Попробовать отменить чужую бронь по прямому URL — должно быть **404** (а не чужая бронь по ошибке).

### 3.6. Админка (`/admin/`, только под `admin`)
- Разделы «Отели» и «Номера» показывают миниатюру обложки/фото в списке.
- В «Бронированиях» видны действия «Подтвердить выбранные» / «Отменить выбранные» (массовые операции).

## 4. Что было исправлено и добавлено в этом проекте

### 4.1. Критические баги (аудит проекта)

| № | Проблема | Исправление |
|---|---|---|
| 1 | Отмена брони работала по GET-ссылке | `@require_POST` на `booking_cancel` |
| 2 | Открытый редирект через `?next=` | Проверка `url_has_allowed_host_and_scheme` |
| 3 | Гонка при параллельном бронировании | `transaction.atomic()` + `select_for_update()` в `create_booking` |
| 5 | Выход выполнялся по GET-ссылке | `@require_POST`, ссылки заменены на POST-формы |
| 6 | Повторный `authenticate()` после валидной формы | `form.get_user()` |
| 7 | `Hotel.rating` принимал любое число | Валидаторы + `CheckConstraint` в БД |
| 9 | Поле `avatar` было, формы загрузки не было | `ProfileUpdateForm` + страница `/users/profile/edit/` |
| 11 | Локальная БД отставала от миграций | Миграции применены |
| 13 | Секреты захардкожены | `SECRET_KEY`/`DEBUG`/`ALLOWED_HOSTS` из переменных окружения |
| 15 | Дублирующая раздача `static()` | Убрана лишняя строка |

### 4.2. Занятие 1 «Данные и выборки» — найденные и исправленные ошибки примера

| Ошибка в исходном примере | Исправление |
|---|---|
| `return cleaned_data` в `RoomSearchForm.clean()` был вложен внутрь `if` — при корректных датах метод вернул бы `None` | `return` вынесен на уровень метода |
| `Room.objects.filter(is_active=True)` — такого поля нет (есть `is_available`) | Исправлено на `is_available=True` |
| `order_by('price')` — поле называется `price_per_night` | Добавлен словарь `SORT_FIELDS` |
| Проверка занятости не фильтровала по статусу брони — отменённая бронь блокировала бы номер | `Room.objects.free_between()` учитывает только активные статусы (`pending`, `confirmed`) |
| Ручная пагинация `?{{ request.GET.urlencode }}&page=N` — дублирует `page=` при уже существующем в адресе | Заменено на `{% querystring %}` |

Реализовано: `rooms/forms.py` (`RoomSearchForm`), `Room.objects.free_between()`,
`RoomListView` (CBV с пагинацией `paginate_by=6`).

### 4.3. Занятие 2 «Файлы и мультимедиа»

- `Hotel.cover`, `Room.image` — `ImageField` с валидацией расширения/размера (`core/validators.py`).
- Заглушка `static/img/no-photo.svg` на случай отсутствия фото, с graceful fallback через `onerror` (см. 4.5).
- Превью миниатюр в админке.
- Сигналы очистки файлов при удалении записи (`hotels/signals.py`, `rooms/signals.py`).
- Форма загрузки аватара пользователя.
- **Импорт/экспорт** (`hotels`): экспорт каталога в **CSV, Excel (.xlsx), PDF, Word (.docx)**; импорт принимает **CSV и Excel**. PDF и Word — сознательно только на экспорт: это форматы для чтения и печати, доставать из них обратно табличные данные ненадёжно, поэтому единственные практичные форматы импорта — CSV и Excel (аналог того, чем реально пользуются такие системы).

### 4.4. Правки этой сессии (финальный аудит)

- **Найден и исправлен баг вёрстки:** 7 многострочных Django-комментариев `{# ... #}` в шаблонах (`navbar.html`, `login.html`, `register.html`, `profile.html`, `list.html` × 2) рендерились как видимый текст на странице — Django-тег `{# #}` **не поддерживает перенос строки** (в отличие от `{% comment %}...{% endcomment %}`). Все 7 случаев переведены на `{% comment %}...{% endcomment %}`.
- Добавлен `onerror`-фолбэк на все `<img>` с `hotel.cover`/`room.image`: пока вы не положили свой файл по заготовленному пути, вместо «битой» иконки браузера показывается SVG-заглушка.
- Расширены `hotels/exports.py` и `hotels/forms.py`/`views.py`: экспорт в 4 форматах, импорт CSV+Excel (было только CSV).
- Добавлены точечные тесты для `seed_hotels`, `seed_rooms`, `seed_bookings` (раньше проверялись только через общий оркестратор `seed`).
- Полная визуальная проверка рендеринга (Playwright) всех основных страниц под гостем, вошедшим пользователем и администратором — реальных ошибок кроме указанной выше не найдено.

### 4.5. Второй финальный аудит (эта сессия) — см. также `ИЗМЕНЕНИЯ_АУДИТ_2.md`

- **Исправлен дефект №4** («Доступность номера не зависит от дат»): раньше
  бейдж «Свободен/Занят» в карточках и на странице номера брался напрямую
  из статичного поля `is_available`, никак не связанного с реальными
  бронями — номер с бронью на завтра мог месяцами показываться
  «Свободен». Теперь `is_available` трактуется как «выставлен на продажу»
  (`RoomQuerySet.on_sale()`), а бейдж считается отдельной аннотацией
  `occupied_today` (`RoomQuerySet.with_today_status()`, через
  `~Exists()`/`Exists()`-подзапрос, как и предлагалось в задании на аудит —
  без N+1, один подзапрос на всю страницу). `free_between()` при этом
  переписан с `.exclude(pk__in=values_list(...))` на `~Exists(OuterRef(...))`
  — тот же результат, но без промежуточного списка id в памяти.
- **Список отелей доведён до того же уровня, что и список номеров**
  (дефекты №8/№14): `/hotels/` был последней страницей каталога без
  пагинации — добавлены `HotelListView` (CBV), `paginate_by=6`,
  сортировка по цене/рейтингу. Цена на карточке отеля и на его странице
  теперь показывается как «от N ₸» — агрегат `Min()` по ценам реальных
  номеров (`HotelQuerySet.with_stats()`), а не отдельное поле
  `Hotel.price`, которое могло разойтись с ценами номеров.
- **Вновь найден и исправлен тот же баг вёрстки, что и в разделе 4.4**
  (многострочные `{# ... #}` вместо `{% comment %}...{% endcomment %}`) —
  на этот раз в 6 местах, добавленных вместе с правками выше
  (`rooms/_card.html`, `rooms/detail.html` ×2, `hotels/_card.html`,
  `hotels/detail.html`, `hotels/list.html`). Проверено — ни один
  комментарий не протекает в отданный браузеру HTML.
- Добавлено 11 новых тестов на оба исправления (`RoomTodayStatusTests` в
  `rooms/tests.py`, `HotelListPaginationAndStatsTests` в `hotels/tests.py`).
- Полная выборка: `python manage.py check`, `makemigrations --check` —
  чисто, миграции не потребовались (оба исправления — новые методы
  QuerySet и вычисляемые аннотации, без изменения полей моделей).
  Визуально проверено через `runserver` на засеянных данных, что бейдж
  и цена «от» отображаются корректно на всех трёх страницах (список
  номеров, страница номера, страница отеля).

**Итог: было 51 тест в исходном присланном архиве → 91 после первого аудита
→ 102 теста сейчас, все зелёные.**

## 5. Куда класть файлы и картинки

Пути уже прописаны в базе данных сидерами — просто положите файл с точным
именем в нужную папку, ничего пересобирать не нужно:

```
media/hotels/covers/demo/grand-astana.jpg   ← обложка отеля «Grand Astana»
media/hotels/covers/demo/almaty-plaza.jpg   ← обложка отеля «Almaty Plaza»
media/rooms/images/demo/single-room.jpg     ← фото одноместного номера в Grand Astana
```

Имя и расширение файла (jpg/jpeg/png/webp) можно сменить на своё — тогда
поправьте путь в соответствующем сидере:
- `hotels/management/commands/seed_hotels.py` → словарь `DEMO_COVERS`
- `rooms/management/commands/seed_rooms.py` → строка с `rooms/images/demo/...`

и запустите заново `python manage.py seed_hotels` / `seed_rooms` (сидеры
идемпотентны — повторный запуск не создаст дублей, только обновит путь).

**Для остальных отелей/номеров** — через админку: `/admin/` → «Отели» или
«Номера» → нужная запись → поле «Обложка» / «Фото номера» → обычная загрузка
файла через форму (это тот же механизм `ImageField`, который изучали на
занятии 2).

Пока файла нет — на сайте вместо него автоматически показывается заглушка
`static/img/no-photo.svg` (это стало ещё надёжнее после правки из раздела 4.4:
даже если путь в базе прописан, а файла физически нет, картинка не «ломается»).
