# HotelHub — запуск и тестирование

Краткое практическое руководство: как поднять проект, наполнить его
демо-данными и прогнать тесты (включая сервисный слой бронирований).

---

## 1. Требования

- **Python 3.12+** (Django 6.0 не работает на более старых версиях).
- ОС: Windows / macOS / Linux.

Проверить версию: `python --version`.

---

## 2. Запуск проекта

Все команды выполняются из корневой папки проекта (там, где лежит `manage.py`).

```bash
# 1. Виртуальное окружение
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate

# 2. Зависимости
pip install -r requirements.txt

# 3. Миграции (создают таблицы, индексы и ограничения в БД)
python manage.py migrate

# 4. Демо-данные (пользователи, отели, номера, брони)
python manage.py seed

# 5. Запуск сервера разработки
python manage.py runserver
```

Открыть в браузере: **http://127.0.0.1:8000/**

### Демо-доступы (создаёт команда `seed`)

| Роль  | Логин | Пароль        |
|-------|-------|---------------|
| Гость | guest | guestpass123  |
| Админ | admin | admin12345    |

Админ-панель: http://127.0.0.1:8000/admin/

## 3. Наполнение данными (seed)

У каждого приложения есть **свой** сидер, а общая команда `seed` вызывает их
по порядку зависимостей: `users → hotels → rooms → bookings`.

```bash
python manage.py seed              # наполнить всё сразу (оркестратор)
python manage.py seed --flush      # очистить демо-данные и создать заново

# По отдельности (например, добавить только отели):
python manage.py seed_users
python manage.py seed_hotels
python manage.py seed_rooms
python manage.py seed_bookings
```

Все сидеры **идемпотентны**: повторный запуск не создаёт дубликатов.
Сидер бронирований (`seed_bookings`) создаёт брони **через сервисный слой**,
поэтому демо-данные проходят те же бизнес-проверки, что и реальные брони.

Порядок важен: номерам нужны отели, броням — пользователи и номера. При
запуске `seed_rooms`/`seed_bookings` раньше зависимостей команда выведет
предупреждение и не упадёт.

## 4. Тесты

### Запуск всех тестов

```bash
python manage.py test
```

Ожидаемо: **51 тест, статус OK**. Тесты используют отдельную БД в памяти —
на рабочие данные (`db.sqlite3`) они не влияют.

### Запуск по приложениям

```bash
python manage.py test core        # главная страница + общий сидер seed
python manage.py test users       # модель User, регистрация/вход, seed_users
python manage.py test hotels      # модель, список, поиск по городу, деталка
python manage.py test rooms       # модель, уникальность номера, поиск, деталка
python manage.py test bookings    # модель + сервисный слой + view
```

### Запуск тестов СЕРВИСНОГО СЛОЯ

Бизнес-логика бронирования (расчёт цены, валидация дат, занятость номера,
создание и отмена брони) вынесена в `bookings/services.py` и покрыта
отдельным классом тестов. Запустить только их:

```bash
python manage.py test bookings.tests.BookingServiceTests
```

Ожидаемо: **14 тестов, статус OK**. Эти тесты вызывают функции сервиса
напрямую, без HTTP — так проверяется предметная логика в чистом виде.

### Полезные флаги

```bash
python manage.py test --verbosity 2      # подробный вывод по каждому тесту
python manage.py test --failfast         # остановиться на первом падении
python manage.py test bookings.tests.BookingServiceTests.test_create_booking_success
```

## 5. Карта тестов

| Файл                | Что покрывает                                                        |
|---------------------|---------------------------------------------------------------------|
| `core/tests.py`     | Главная страница, статистика витрины; общий сидер `seed` (в т.ч. `--flush`, идемпотентность). |
| `users/tests.py`    | Кастомная модель User (phone), регистрация с авто-входом, вход/выход, защита профиля, `seed_users`. |
| `hotels/tests.py`   | Модель Hotel, список только активных, поиск по городу (в т.ч. кириллица строчными), деталка и 404. |
| `rooms/tests.py`    | Модель Room, уникальность номера в отеле, поиск по отелю и типу, скрытие занятых, деталка. |
| `bookings/tests.py` | Модель (nights/total_price); **сервисный слой** (14 тестов); тонкие view (права, сценарий брони). |

## 6. Частые вопросы

**Поиск по городу русскими строчными буквами ничего не находил.**
Исправлено: SQLite приводит к нижнему регистру только латиницу, поэтому в
`core/apps.py` зарегистрирована Unicode-совместимая функция `LOWER` — теперь
«алматы» находит «Алматы».

**Тесты идут медленно (~1 минуту).**
Основное время занимает хеширование паролей при создании пользователей —
это нормально для набора с реальной аутентификацией.

**Нужно начать с чистой базы.**
Удалите `db.sqlite3`, затем `python manage.py migrate` и `python manage.py seed`.
Либо не удаляя файл: `python manage.py seed --flush`.
